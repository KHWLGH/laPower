# 0.2.4 - 2026-10-13

## Changed

- Sampling rates below the meter's native rate now average every frame in each window instead of keeping the frame with the largest absolute current. Voltage, current, power and D+ / D− are averaged; the timestamp, CC readings and temperature come from the last frame. This includes the default 4 samples/s setting. WITRN at 100 samples/s and POWER-Z at 1000 samples/s are unchanged; spikes shorter than the selected interval are smoothed out. Replaying an existing 70-minute WITRN K2 wireless-charging recording reduced cumulative-energy error at 100 ms / 250 ms / 1 s / 10 s from +0.90% / +1.18% / +1.71% / +2.84% with peak selection to within ±0.11% with averaging.
- Complete constant-value data blocks share storage, reducing memory use for empty channels, steady signal lines, recording-segment IDs and sampling intervals. CSV import finalization fills missing values block by block while preserving exact values and the complete recording history.
- Removed the automatic platform-following window-style option. Windows and Linux default to Windows-style controls and migrate existing automatic settings; macOS continues to use native traffic-light controls.
- Release notes are archived by version under `changelog/<version>/`, including the earlier Chinese-only history; the root changelog is now a version index. New releases provide English and Simplified Chinese Markdown, with only the Chinese draft maintained during development. Added preparation and preview commands; GitHub Releases show English first and place Chinese in a collapsible section, retaining installer checksum verification and safe draft retries.
- Streamlined documentation: README files, user guides and development/build guides remain available in four languages, with external temperature-service instructions consolidated into the development guides. Architecture, performance and protocol-crate documentation is maintained in English and Simplified Chinese; duplicate entry points and one-off historical reports were removed.
- Refreshed the 0.2.4 light/dark preview images in Simplified Chinese, Traditional Chinese, English and Japanese, covering monitoring, PD analysis, protocol control and settings. Screenshots retain the full application title bar and use the same 120 seconds of simulated data.

## Fixed

- Queued WITRN reports read after a delayed reader wake-up no longer share a read-time timestamp and get merged away in a single 100 samples/s selection window. The reader drains the queue first and reconstructs timestamps using the device cadence (≤ 10 ms). In an existing 70-minute macOS recording containing 425,121 points, the old logic merged away about 149 frames (0.035%) across 84 delayed wake-ups, with up to 19 frames lost in one wake-up.
- Drain old WITRN reports before starting, pausing or resuming recording, or changing the sampling rate, and fence reconstructed timestamps at the new recording boundary. This prevents stale backlog from entering a new recording segment or collapsing to relative time zero. Acquisition stops explicitly if the drain limit is exceeded, preserving already-recorded data.
- Fixed undercounted Wh / mAh when opposite current directions cancel within a coarse sampling window. Signed mean current still indicates direction, while power, energy and capacity use per-frame mean magnitudes. Range statistics, CSV exports and temporary recovery files preserve the same integration semantics; CSV adds `CurrentMagnitude(A)` only when needed and remains compatible with older files.
- The system-following language option now shows the detected system language even after manually switching the interface language. Unsupported system languages retain their actual names while the interface falls back to English.
- Simplified and Traditional Chinese interfaces on Windows now prefer Microsoft YaHei UI, improving small-text readability compared with Microsoft JhengHei. JhengHei remains a fallback for missing glyphs, and form and chart fonts switch together.
