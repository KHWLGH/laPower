# 图表暂停与交互性能修复验收

日期：2026-10-16。本轮在已有有序降采样上优化绘制、暂停接管和调度。实施前保存了 393 个仓库文件、未提交 diff、测试、基准脚本与原生二进制，位于本机忽略目录 `bench/results/chart-followup-before/`。测试归档追加 `.snapshot` 后缀，防止 Node 自动执行。此前产物继续保留；本轮对照不使用最初 Git 提交。

## 实现

每通道把有效连接段组成一个缓存 Path2D，一次填充多个独立闭合子路径；缺测、真实时间、重复时间和基线规则保留。绘制仍按通道依次填充、描边，减少相邻小区域的透明合成接缝。普通区域直接在主画布填充。屏幕坐标的累计纵向折返超过绘图区宽度 64 倍时，`chart-fill.js` 按有序线段与基线解析计算像素覆盖面积；跨基线拆分积分，缺测不积分，重复时间的零宽区域不增加面积。所有子像素区域先累计，再应用一次透明度，在同一共享位图中覆盖不透明描边并一次提交，保持填充在描边下面的效果。使用三个行差分缓冲和端点事件计算线性积分，避免按每条陡坡遍历所有行，也绕过 Canvas 复杂填充的同步与延迟栅格化。选择随坐标缓存失效，不改变候选点或公开设置。没有位图能力时仍使用缓存的相同闭合路径；无填充回退通道由 uPlot 描边一次。

解析覆盖按线段端点及边缘行的事件推进，跳过随后被本通道不透明描边完全覆盖的区域，保留所有可见像素的面积。某列的一个不透明区间确实包含全部有效线段时，可见填充精确等于区间外到基线的条带：仍累计有效横向跨度，保留 NaN 空档和亚像素覆盖，不为被遮挡的折返区域积分。均匀条带与已有相同颜色合成时只计算一次颜色，整段写入。相邻位图通道在共享缓冲里依次执行 source-over 填充、覆盖不透明描边，最后一次提交；遇到普通 Canvas 填充先提交已有位图，保持通道叠放顺序。这样既避免逐段透明合成，也减少四个填充通道各自上传整图的开销。临时位图转置存储，使同一屏幕列的像素连续，提交时交换坐标；单独转置的探索没有稳定收益，不作为提速依据，条带、事件跳转与合并提交均经后续完整矩阵复测。

坐标与合并后的屏幕列区间使用有界缓冲；几何、坐标范围、尺寸、DPI、基线或描边宽度改变时使相关缓存失效。保护重绘可以复用相同几何。全图共用一张临时位图，CPU 像素只清理上次写入的范围。测试覆盖极值移动、隐藏通道和窗口缩小后的残影。

暂停先同步已入库但尚未刷新标签的窗口，取消录制期间尚未发布的旧准备任务，保留完成的索引前缀。热索引直接准备精细投影，给予 16 ms 有界同步预算，避免通常只需 10–12 ms 的查询被 8 ms 预算切断后多等一个任务；后台准备期间保留原画面，原画面不计为暂停首图。普通交互仍使用 4 ms 预算。冷暂停提交完整录制投影并补有界尾部，实际主图 draw 后才启动后台细化，完成后原子替换。松手与细化刷新复用已有绑定。主图先提交，导航图合并到后续帧。暂停后自然推进的 full／follow 尾点窗口补排刷新，防止细化先消费显示任务而漏掉最终尾点范围。

复杂度保护仍需使用桶渲染的中等缩放窗口，保留已测得的填充保护，不在低于四点／CSS 像素时反复恢复昂贵填充。能采用受控原始点路径的窗口仍按原规则保留填充；稳定窗口的拖动与松手几何一致。

每次暂停固定请求时间、请求时记录长度、数据源代数和窗口意图。诊断关联同步／协作准备 CPU、坐标、填充、区间、位图、draw 和后续帧；记录仍有界，不在样本循环打点。尾点正常入库与确认，暂停 Promise 继续仅等待原生尾点栅栏，恢复文件同步另行执行。

设备诊断改为按连接会话累计检测到的序号空洞估计和内容已验证的重放数，队列重启不清零；变更日志最多五秒一次，断开汇总。不增加自动暂停、补点或提示。

`chart-extrema.js` 与 `chart-buckets.js` 相对本轮基线字节未变。360 万点索引仍为 **21,823,488 B**，100 万点为 **6,242,304 B**。绘制缓冲另计；原始样本、统计、积分、CSV、公开设置与记录容量换算未变。

## 测量口径与基准纠正

公开填充设置使用百分数，且只有电压、电流、功率、温度四路。此前手动脚本把 12% 错传成 `0.12`，并额外填充 D+/D−/CC；旧报告中的相关“12%”表述不成立。本轮最终脚本传 `12`，默认只对四个公开通道开启填充，八路曲线仍全部显示。`--fill-channels 8` 可复现额外压力场景。

错误透明度的早期结果以及软件后备、转交位图、填充时改用矢量描边的探索产物均保留，不混入最终汇总。全部区域都放入临时位图会使普通信号的同步提交超过 60 ms；全部直接提交主画布则在强交变时测得秒级延迟栅格化。仅依靠复杂度切换目标的版本通过冷暂停验证，但完整矩阵又发现强交变热暂停仍可超过 1.6 秒；切小 Path2D 子路径也未稳定解决。最终用解析覆盖绕过该复杂填充，原测得填充保护继续保留。八路全部 12% 填充的额外探索也出现过位图提交长阻塞，不能将早期探索误报为达标。

解析覆盖测试使用独立的逐像素多边形裁剪与面积算法作参考，覆盖正负基线、斜坡、阶跃、重复时间、NaN 断段、多条亚像素线段、60 组固定种子的随机几何及四档透明度，输出 alpha 与参考相差至多一个 8 位色阶。另行检查转置与正常布局逐像素相同、遮挡区不写入、多通道 source-over 混合，以及位图／普通 Canvas 混合时的提交顺序。

首张完整图必须覆盖暂停请求时的记录长度；热首图必须为精细图。尾点全部绘制、最终精细图、后续 rAF 和原生栅栏单独记录。表中栅栏耗时为 `stopRecording()` 调用至其暂停 Promise 完成，包含 IPC 与调用期间的同步工作，不是纯 USB 读取时间；Promise 不等待图表 draw 或磁盘同步。Canvas draw 回调和 rAF 都不是物理显示器呈现时间。所有分位数采用 nearest-rank，同机运行不等于控制了电源、频率和全部后台负载。

## 最终结果

最终生产源码对应 `chart-followup-matrix-final-strip/`、`chart-followup-webview-final-strip/` 和 `chart-followup-hardware-final-strip/`。此前 `final-hybrid`、`final-coverage`、`final-events` 等目录是中间实现，完整保留，但不是本节的最终验收。生产源码在每组运行前后指纹一致，原生程序还逐个核对实际内嵌的四个图表模块。

浏览器完整矩阵包含 384 组：两版 × 两档点数（100 万／360 万）× 两种信号 × 四档 DPI × 三／八通道 × 填充开／关 × 三轮。修复版 192 次热暂停首图全部为完整精细投影，192 次冷暂停全部先完整粗图再一次升级；没有用粗图或旧画面满足热首图指标。

## 硬件边界与异常

使用真实 KM003C（`5FC9:0063`，序列号 `025860`）USB bulk / AdcQueue 1KSPS、WebView2 155.0.4283.45、DPI 1.5。两版从同份 1,434,583 点实测历史经原生恢复文件与导入 Worker 开始，再进行真实采集和恢复文件写入；这不等于重新不中断采集 143 万点。八通道带填充冷热暂停各至少 20 轮，三通道及无填充组合各三轮。

实测历史七路有有限值，温度缺测；接线为低电平信号，无受控带载强交变。真实 360 万点不中断采集、有效温度、受控负载和断电恢复仍未验收，不以合成矩阵替代。没有执行仪表电压或协议诱骗控制。

重连探索有一次触发既有的“KM003C AdcQueue 时间未递增；采集已停止”保护。错误、流状态与清理结果保留在 `chart-followup-hardware-verified/hardware.json`；该次不计入性能分布，也没有改动时间校验规则来绕过失败。较少样本的早期转交位图探索还发现过尾点未完全绘制的断言失败，需与最终尾点检查一并核对。
